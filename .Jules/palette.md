## 2025-01-08 - Keyboard Inaccessible Custom Elements and Icon Buttons
**Learning:** This app frequently relies on standard `div` elements customized as interactive elements (like `#sigil` acting as a start button on splash screens) and empty button elements utilizing CSS `::after` pseudo-elements for icon graphics without semantic text labels. This presents a critical accessibility pattern flaw: these elements lack inherent keyboard interactivity (`tabindex`, `onkeydown`), screen reader affordances (`role="button"`, `aria-label`), and robust visible focus styles (`:focus-visible`).
**Action:** When working on UX enhancements in this codebase, explicitly audit `div` elements functioning as buttons and pseudo-element-based icon buttons for missing ARIA attributes, keyboard support, and visible focus indicators.
